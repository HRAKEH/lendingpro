**Адрес:** https://zdrava.ru/flebodia/
**Статус:** адрес выбран; фактическая публикация не подтверждена.

Пользователь подтвердил размещение Флебодиа **в подпапке основного домена**, а не на поддомене или новом домене.

## Файлы из исходного ZIP

В архиве `flebodia-site-for-developer.zip` лежат:

```
public/
  index.html
  assets/
    hero.webp
    rest.webp
```

В Timeweb в **документальном корне сайта zdrava.ru** (реальный путь нужно проверить в панели хостинга, не предполагать, что это обязательно `public_html`) создаётся подкаталог `flebodia/`:

```
<корень сайта zdrava.ru>/
  index.html              # основной сайт; не заменять
  flebodia/
    index.html
    assets/
      hero.webp
      rest.webp
```

Переносится содержимое `public/`, а не сама директория `public/`. Проверены ссылки HTML: локальные изображения используют относительные пути `assets/hero.webp`, `assets/rest.webp`; внутренние якоря также относительные. HTML править для подпапки не требуется.

## Пошагово
1. Timeweb → список сайтов → найти сайт, обслуживающий `zdrava.ru`, и **проверить документальный корень**.
2. Открыть эту папку файловым менеджером; создать `flebodia/`.
3. Распаковать содержимое `public/` в `flebodia/`.
4. Проверить `https://zdrava.ru/flebodia/` и что `https://zdrava.ru/` не изменился.
5. Проверить hero/rest, якорную навигацию, мобильный экран и переходы на Ozon.
6. Если страница не открылась, проверить настройки маршрутизации основного сайта, права файлов и SSL домена.

Не публиковать коммерческие/медицинские утверждения без сверки с утверждённой этикеткой. Изготовитель в исходных материалах указан неполно.
